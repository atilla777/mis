# Содержательная сверка `/mis-bug`

Это случаи для проверки инструкций и будущего модельного пилота, не результаты
реального исполнения команды. Unit tests рядом проверяют только поставку пакета.

| Вход / условия | Ожидаемый результат |
| --- | --- |
| «После паузы герой продолжает двигаться»; есть код/тесты | Ограниченное чтение/безопасная проверка; reported vs observed, ревизия, actual/expected/repro и регрессии в Bug; код не исправляется. |
| «Хочу повтор матча с тем же seed после поражения»; сейчас кнопки нет | Native bug с природой «запрос поведения», текущий/желаемый сценарии, границы (что сохранять/сбрасывать) и наблюдаемая приёмка; отсутствие старого дефекта не blocker. Потом обычный run. |
| «Бой иногда зависает», среды/логов нет | Сохранить сообщение, доступные факты и точные пробелы; неизвестное не выдумывать, root cause не обязателен, готовность к run не заявлять без основания. |
| Точный all-status дубль с новым логом / повтор после сбоя записи | Прочитать исходные полные поля, сохранить полезную добавку без потери чужого, reuse ID; повтор no-op. Не создавать до reconciliation неизвестного эффекта. |
| Закрытая похожая ошибка / новая регрессия | Закрытый дубль не reopen; для новой регрессии объяснить отличия и ссылку. Неясная идентичность требует уточнения; не создавать на неполном inventory. |
| Exact Task ID / неверный ID / чужой claim | Task остаётся Task при разрешённом дополнении; неверный ID не порождает замену, чужой claim блокирует запись. Нет claim/close/type conversion. |
| Новое ожидание противоречит product | Один понятный вопрос о существенном решении, ответ и основание остаются в Beads. Не переписывать product и не выдавать предложение за принятое. |
| Запрос нескольких крупных игровых механик | Сохранить проблематику и границы, не обещать один run; рекомендовать plan по ID без автоматического Epic/декомпозиции. |
| Нет remote permissions после локальной записи | Вернуть реальный ID/read-back и непроверенную публикацию с blocker. Git push не заменяет Dolt receipt, создание не повторяется. |

Для определённого посильного запроса свежая проверка blockers/ownership должна
предшествовать рекомендации `/mis-run <ID>`. Команда только рекомендуется.
