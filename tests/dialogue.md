# Проверочные сценарии диалога MIS

Содержательная сверка инструкций, не автоматический тест поведения модели.
Правила: `skills/mis-proj-lib-common/references/dialogue.md`.

1. **Одиночное уточнение без interview.** Для сохранения настроек есть выбор:
   только на устройстве или между устройствами. Координатор даёт контекст и
   последствия, задаёт один ❓ вопрос без номера; варианты нумеруются, первый
   💡 рекомендуемый с причиной по известной цели, доступен свой ответ. Нет
   второго вопроса о входе в аккаунт до ответа на первый.
2. **Продолжение интервью.** Пользователь принял локальное хранение. Краткое
   ✅ подтверждение не включает невыбранный формат файла. Только следующий
   существенный вопрос; MIS не использует разрешённый portable-методикой блок.
3. **Фактический вопрос.** Неизвестен желаемый видимый заголовок экрана, источники
   ответа не содержат. Один открытый вопрос с контекстом; нет выдуманных вариантов
   и «рекомендации». При достаточных данных нет интервью и формальных пауз.
4. **Непонятные термины.** Внутренний факт «Dolt S/R diverged» не передаётся как
   единственное объяснение. Сообщение объясняет, что локальная и общая история
   задач содержат разные изменения, что уже сохранено, почему публикация
   остановлена и какой шаг нужен. Необходимый термин поясняется при первом
   употреблении; команды/пути не искажаются. Без человеческой развилки нет
   формального «можно продолжить?».
5. **Install/update до review.** Конфликт существующей настройки или локальная
   правка требуют обсуждения раньше review. Обе операции читают common и ресурс
   до общения; first-install получает их из проверенного внешнего checkout,
   даже если skill tool ещё не видит MIS. Никаких требований установить RIS.
6. **Форма выбора и восстановление.** Форма содержит ровно один вопрос, первый
   вариант явно рекомендуемый с причиной, доступен свободный ответ. Текстовое
   меню не дублируется. После потери контекста или смены версии восстанавливается
   применимый ресурс; предположение не помечается ✅ подтверждённым.
