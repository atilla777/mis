# MIS Sessions · Omarchy

Раскрывающийся список задач диспетчера и до четырёх **обычных окон OpenCode**
на проект. Проектам соответствуют именованные рабочие столы Hyprland.
Herdr, tmux, новый scheduler и плагины OpenCode не нужны.

## Установка из проверенного checkout MIS

Нужны Omarchy Shell (Quickshell), Hyprland **0.56 с Lua/custom layouts**,
Kitty, `/usr/bin/python3`, OpenCode 2 shared service и Beads в PATH desktop-сессии.
При несовместимом API пульт показывает ошибку, не угадывает состояние по экрану.

Пакет устанавливается отдельно от `/mis-install` и `/mis-update`.
Из корня проверенного MIS checkout, **если назначения ещё нет**:

```sh
mkdir -p ~/.config/omarchy/plugins
ln -s "$PWD/integrations/omarchy/mis.sessions" ~/.config/omarchy/plugins/mis.sessions
```

Не используйте `ln -sf`: существующий plugin может содержать ваши изменения.
Symlink означает, что обновления этого checkout меняют установленный plugin;
не подключайте непроверенный WIP checkout.

В конец `~/.config/hypr/hyprland.lua` добавьте одну строку (сначала сохраните backup):

```lua
dofile(os.getenv("HOME") .. "/.config/omarchy/plugins/mis.sessions/layout.lua")
```

Для нестандартного XDG config path используйте фактический путь. Затем:

```sh
hyprctl reload
hyprctl configerrors
omarchy-shell shell rescanPlugins
omarchy plugin enable mis.sessions right
```

Не продолжайте при ошибках Hyprland. Включение виджета запускает автоматическое
обнаружение и открывает до четырёх клиентских окон на проект **без отправки prompt**.
Существующие рабочие столы/биндинги не заменяются. Имена `mis-<hash>` и классы
`mis.sessions.*` зарезервированы пультом; не используйте их для других окон.

## Использование

- Клик **MIS** на панели — список проектов и задач. Без задач — обычный `MIS`.
  `▶ N` акцентным цветом — работают N задач, `Ⅱ N` — N задач на паузе.
  Красный `? N` — N задач ждут ответа или разрешения; `! N` — ошибки задач,
  `!` — ошибка обновления. Метки могут показываться одновременно, красный имеет
  приоритет. Счётчики общие по всем проектам; дочерние сессии входят в задачу.
- При ожидании ответа в popup есть подсказка, на кнопке проекта — `? N`, у задачи —
  «Ждёт вашего ответа или разрешения». Откройте задачу, чтобы увидеть сам вопрос.
  Ожидание определяется native pending forms/permissions, не idle или текстом модели.
  Устаревшие проекты не входят в счётчики текущих состояний и отмечаются `!`.
- Проект выбирается кнопкой в списке; диалог — кликом по задаче.
- Уже показанная задача фокусируется. Другая заменяет последний выбранный слот
  того же проекта, сохраняя само окно и остальные три диалога.
- `Super+стрелки`, `Super+F`, переключение рабочих столов — обычные биндинги
  Omarchy (если вы не переопределили их). Пульт не добавляет биндинги.
- В раскрытом списке также работают стрелки/Enter/Esc и `r` для обновления.
- Новые задачи занимают только свободные слоты и не перехватывают фокус.
- Завершение подтверждается Beads closed **и** отсутствием active/pending во всём
  native семействе сессии. Idle/failed/waiting не убираются как завершённые.
- История остаётся в OpenCode. Пульт не удаляет сессии или Beads-записи.

Обновление — раз в 15 секунд после доступности процесса. Полный inventory
OpenCode читается постранично, поэтому большое количество исторических сессий
увеличивает задержку; это не SLA. Выбор задачи повторно проверяет точную связь
без полного пересканирования истории. Диагностика проекта не скрывает другие
проекты, а прошлые окна недоступного проекта сохраняются с признаком stale.
При глобальной ошибке сохраняется весь предыдущий снимок.

Состояние интерфейса: `$XDG_RUNTIME_DIR/mis-sessions/state.json` (0600, каталог 0700).
Это только снимок/слоты/фокус, не новый task tracker. Один helper пишет состояние
под flock; несколько мониторов не должны запускать дублирующиеся окна.
Ответы API читаются через `opencode api` с native discovery/authentication.
Заголовки/пути в QML — plain text, аргументы запуска не исполняются как текст задачи.

При смене слота завершается **только дочерний TUI-процесс** (SIGTERM, при зависании
SIGKILL), не сервер OpenCode и не process group. Использование `--session` имеет
native create-if-missing семантику: пульт сначала делает GET существующей сессии;
конкурентное удаление между GET и запуском клиента полностью исключить нельзя.
Не удаляйте сессии, пока пульт подключается к ним.

## Отключение

```sh
/usr/bin/python3 -B integrations/omarchy/mis.sessions/sessions.py pause
omarchy plugin disable mis.sessions
```

После отключения виджета клиентские окна остаются обычными окнами, их можно
закрыть штатно. Серверные задачи продолжаются. Чтобы снова разрешить автоматику,
включите виджет и выберите задачу из списка. Для полного удаления уберите только
свой symlink и добавленную строку `dofile`, затем reload/configerrors. Не удаляйте
каталог runtime, пока открыты viewer-окна. Пульт не регистрирует systemd services.

## Проверки из корня MIS

```sh
python3 -B -m unittest discover -s tests -p test_sessions.py -v
omarchy plugin validate integrations/omarchy/mis.sessions
python3 -B tests/sessions_qml_smoke.py
```

Опциональные **живые** проверки, без вызовов модели:

```sh
python3 -B tests/sessions_client_smoke.py
python3 -B tests/sessions_desktop_smoke.py
python3 -B tests/sessions_viewer_smoke.py
```

Client smoke создаёт disposable Git checkout/OpenCode session, запускает только
фиксированную shell-команду и проверяет её завершение после отключения TUI.
Desktop smoke временно загружает layout и создаёт четыре dummy Kitty окна.
Viewer smoke до установки (отказывается перезаписывать существующий runtime
state) создаёт пять disposable сессий, открывает четыре TUI, заменяет выбранный
слот пятой сессией и проверяет сохранность всех пяти серверных сессий.
Эти scripts закрывают/удаляют только собственные fixtures. После GUI smoke
`hyprctl reload` убирает временно загруженные правила, если plugin не установлен.
Они не доказывают поведение во время реальной генерации модели.
