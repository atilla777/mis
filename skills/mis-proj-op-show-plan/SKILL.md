# Компактный статус MIS

Работай в текущем контексте, на языке пользователя. Результат — один ответ,
без сохранения отчёта. Никаких persistent writes: init/install/migrate, claim,
update/close/repair, Git/Dolt pull/fetch/push, синхронизации или запуска следующей
работы. Не превращай запрос статуса в планирование или выполнение.

## Область и чтение

1. Установи root **выбранного проекта** из текущей рабочей копии и его инструкций,
   не из пути установки скилла. Загрузи `mis-proj-lib-common` и
   `mis-proj-op-beads`; применяй только их правила чтения. Проверь workspace и
   capabilities по Beads-операции. Не требуй product/spec, remote или готовности
   execution-среды просто для просмотра трекера. Нет БД/доступа — сообщи пробел,
   не инициализируй. Все issue/edge reads выполняй через `bd --readonly`.
2. Без аргументов получи **полный all-status inventory**, без лимита, всех типов
   по Beads-операции. Закрытые записи нужны для счётчиков и проверки связей.
   С точным ID прочитай его actual type и рекурсивно всех прямых детей, включая
   закрытых; необходимые ancestors и внешние blockers читай точечно, без
   независимых внешних деревьев. Допустим Epic, Task или Bug ID. Неизвестный ID —
   ошибка чтения, не пустой план. Неоднозначный ID/root — только нужное уточнение.
3. Построй временную карту ID и **раздельные** связи membership и
   blocked → prerequisite. Parent — только подтверждённое поле/native edge,
   не префикс ID. Для каждого контейнера проверь полный direct-child set; для
   каждой незакрытой записи — typed blocks и состояния endpoints. Brief omission
   не доказывает отсутствие поля/связи; дочитай нужные точные rows/edges.
4. Проверяй exit codes, JSON, scope, уникальность ID и полноту. Truncation дочитай
   из полного сохранённого вывода; не ставь скрытый лимит. Ошибки, неизвестные
   статусы/типы, missing parents и циклы явно сохрани как диагностику. Не прячь
   неизвестные типы или историческую иерархию и не преобразуй их в Task/Feature.
   При concurrent изменениях повтори затронутые чтения либо укажи несогласованность;
   не обещай транзакционный снимок из нескольких CLI-чтений.

## Один компактный вложенный список

Каждая незакрытая запись в области — ровно одна основная строка. Используй
Markdown `-` с двумя пробелами на уровень; каждый child непосредственно под своим
parent, без промежуточных абзацев. Standalone записи — отдельная группа «Без вехи»,
без искусственного Epic. Цвета Epic назначай стабильно по ID из палитры
🔵 🟢 🟠 🟣 🟡 🔴, с повтором только после исчерпания; это не статус/приоритет.

Пример (условные ID):

- 🔵 **Авторизация** · `mis-a12` · закрыто 3/6 задач
  - ○ `mis-a12.4` Вход по почте
  - ▶ `mis-a12.5` Восстановление пароля
  - 🔒 `mis-a12.6` Подключить OAuth · ждёт `mis-b07.2`

- 🟢 **Готовность к разработке** · `mis-b07` · закрыто 1/2 задач
  - ○ `mis-b07.2` Настроить секреты CI

**Без вехи**
- 🐛 `mis-c03` Исправить повторную отправку формы

○ задача · ▶ в работе · 🔒 заблокирована · 🐛 ошибка

Правила компактности:

- Точные ID в inline code, настоящие заголовки без переписывания. Не копируй
  description/acceptance/notes, ссылки на spec, даты создания и журналы этапов.
- Обычный `open` не печатай; тип task также не повторяй. `in_progress` обозначай
  ▶ (это только запись в Beads, не доказательство работающего агента).
  Native `blocked` или активный prerequisite обозначай 🔒; started + blocked —
  ▶ 🔒. Bug всегда сохраняет 🐛, плюс ▶/🔒 при необходимости. Любой иной статус
  печатай явно raw value; неизвестный тип — явной меткой. Не теряй исключения
  ради компактности. Обычные P2/P3/P4 скрыты; P0/P1 показывай. Unknown priority
  обозначай неизвестным. Исполнителя показывай при наличии; срок — просроченный
  или существенно влияющий на следующее действие.
- Активные blockers показывай на **зависимой** строке как `ждёт <ID>`; заголовок
  endpoint добавляй, если его нет в дереве. Внешний endpoint — лишь inline
  контекст, не отдельная ветка. Закрытые prerequisites не блокируют; не выводи их
  без специальной причины. Неизвестный endpoint — `блокер <ID> не проверен`,
  не «блокировок нет». Если native blocked без известной причины — укажи это.
- Закрытые Task/Bug скрыты. Закрытый ancestor с незакрытыми потомками остаётся
  только как `закрыта, контекст`; точно выбранный закрытый root также сохраняй
  как контекст. Open Epic без незакрытых детей не скрывай.
- Счётчик Epic — закрытые/все **прямые Task/Bug**, не рекурсивные итоги. Если есть
  другие direct-child types, подпиши `записей` и считай полный direct-child set.
  Неполное чтение → `состав не проверен`, не выдуманные числа. После дерева
  кратко поясни: счётчики — статусы задач, не достижение критериев вехи.
- Циклические/противоречивые связи и missing parents — группа «⚠️ Связи не
  подтверждены», каждая затронутая запись один раз; не выдумывай reparenting.
- Легенда один раз после дерева, только используемые обозначения. Нет записей —
  «Незавершённых работ нет» только при полном успешном чтении. Ошибки полноты
  явно перечисли после доступной части; не выдавай её за весь план.

## Одно следующее действие

В конце ровно одна рекомендация, **не запуск**. Сначала своё начатое незавершённое
Task/Bug, затем незаблокированная Task/Bug по priority, created time, ID. Чужой
assignee не разрешает takeover; предложи координацию вместо автоматического run.
Неизвестные поля порядка/готовности не объявляй проверенными.

Перед рекомендацией `/mis-run <ID>` точечно проверь собственные требования,
acceptance и actual blockers кандидата по execution resource Beads-операции
(**только чтение**, без claim/готовности Git-публикации). Отсутствие blocks само
по себе не доказывает готовность. Если данных недостаточно, все работы blocked,
контейнер без незакрытых задач требует проверки собственных критериев или план
пуст — предложи один `/mis-plan <цель или ID>` с конкретной причиной; не создавай
задачи и не объявляй Epic достигнутым. Ограниченная ID-область не расширяется
выбором независимой внешней задачи. Не делай полный аудит spec/Git/Dolt истории
ради дерева; непроверенные публикации/критерии не выдавай за подтверждённые.
