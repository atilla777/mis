# Выделить ближайший проверяемый результат

Получай от caller цель, применимые требования и ограничения, наблюдаемое состояние
с доказательствами, существующие открытые/начатые/завершённые работы и границу
планирования. Не требуй каталогов, трекера, других скиллов или design. Отделяй
заданные решения от предложений, фактов и неизвестного. Файл или закрытая запись
сами по себе не доказывают достигнутый результат.

1. Выдели значимое проверяемое состояние, нужное для цели. Для продуктового
   результата проверь основной сквозной сценарий, ошибки и отрицательные/
   количественные ограничения; для технического — наблюдаемую готовность системы
   или устранение конкретного ограничения. Не выдумывай пользовательскую механику
   для технической работы.
2. Начни с одной вехи; несколько нужны только для разных самостоятельных
   результатов. Одной небольшой работе может быть достаточно Task **без Epic**.
   Документы, слои, проектирование, review и публикация не задают границы вех.
3. Ближайшую веху опиши достаточно для выделения Task: цель, границы/исключения,
   наблюдаемые критерии, источники (адрес + раздел, версия если известна).
   Дальние результаты оставь крупными, без детальной технической декомпозиции.
4. Сверь смысл с существующими работами, а не только заголовки. Сохрани известные
   идентичности и выполненное; не планируй повторно доказанный результат.
   Проверь текущие интерфейсы и существенные риски лишь настолько, насколько они
   влияют на границы. Не превращай это в обязательное проектирование.
5. Проверь покрытие цели, пропуски, пересечения и необходимость каждой границы.
   Зависимости обозначай явно как «зависимая работа → необходимый результат» с
   причиной; не путай с приоритетом. Проверь циклы и внешние предпосылки.
   Существенное неизвестное блокирует только зависимые выводы: не придумывай ответ.

Верни ближайшую веху (или обоснованный standalone), крупные дальние результаты,
критерии, источники, покрытие/пробелы, необходимые зависимости и вопросы с их
влиянием. Локальные названия предложений — не Beads ID. Не принимай спорные
продуктовые решения, не записывай файлы/трекер и не начинай выполнение.
