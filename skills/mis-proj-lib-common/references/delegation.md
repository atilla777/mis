# Профили и делегирование MIS

Это политика вызывающего flow, не новая методика и не настройка моделей.
`standard` и `advanced` — ID доступных OpenCode-агентов, не названия моделей.
Их модели/варианты/разрешения задаёт пользователь глобально или в проекте.
Не передавай model override и не устанавливай/переписывай профили автоматически.
Не считай два профиля доказательством разных моделей или разной мощности.

## Выбор исполнителя

| Работа | Исполнитель |
| --- | --- |
| Поиск и сбор фактов без принятия сложных решений | `explore` при наличии, иначе `standard` или координатор |
| Ограниченная реализация, тесты, локальное исправление по достаточному контракту | `standard` |
| Формирование/существенное уточнение требований и продуктовые развилки | `advanced` |
| Архитектура, проектирование, сложный UX/UI-дизайн, неоднозначная декомпозиция | `advanced` |
| Независимое review и re-review | Только отдельный контекст `advanced` |
| Статус, точная запись принятого плана, Git/Beads-механика | Координатор без лишней делегации |

Координатор ведёт flow и единый диалог. Он может сам выполнить простую
ограниченную работу, если уже выбран профиль `standard`; при неизвестном или
ином основном профиле ограниченную реализацию делегируй `standard`.
Не переключай модель основной сессии ради этапа. Для простого готового плана
не нужен advanced: оформление достаточных критериев не равно их формированию.

Направляй нерешённую часть в `advanced`, когда требуется выбор решения при:

- изменении контрактов нескольких подсистем или публичного API;
- рисках безопасности/доступа, миграции или потери данных;
- конкуренции, трудновоспроизводимом сбое либо неизвестной причине после
  целевого исследования;
- существенной неоднозначности требований или конкурирующих архитектурных,
  продуктовых либо UX/UI-вариантах.

Не считай размер diff единственным признаком сложности. Сбор фактов можно
оставить standard; при эскалации передай факты, варианты и конкретный вопрос,
а не поручение заново выполнить весь flow. После достаточного решения реализация
обычно возвращается standard; сложный неотделимый участок можно поручить advanced.
Не повторяй слепо неудачные попытки и не запускай обязательное проектирование
там, где достаточно существующего контракта.

`implementation_mode: standard|tdd` — независимый выбор тестовой стратегии
из правил проекта, **не модельный профиль**. Оба агента следуют той же стратегии.

## Контракт поручения

Передай субагенту:

- одну цель/вопрос и ожидаемый результат;
- принятые требования, ограничения, exclusions и оставшиеся неизвестные;
- точный каталог/worktree, релевантные исходники/ID и проверенную версию кандидата;
- нужный portable/project skill и пути его условных ресурсов; субагент начинает
  с нового контекста и не наследует загруженные родителем методики;
- разрешённые пути и действия, применимые правила и команды проверок.

Получай решения с основаниями, изменённые пути/версию при записи, реальные
проверки, риски и остаток. Координатор проверяет результат и сохраняет принятые
решения в существующих native полях Beads/spec по flow, без handoff/review-файла.
Фиксируй в существующем результате/отчёте профиль, ID контекста, область/версию
и причину существенной эскалации; не выдавай запрошенную модель за наблюдённую.

Интервью идёт через координатора: advanced возвращает пробелы/вопросы,
координатор задаёт их пользователю один раз и передаёт ответы. Субагент не
принимает отсутствующие продуктовые решения за пользователя. В `mis-plan`
уточнение требований не разрешает запись в авторский `docs/product/`.

## Изоляция и недоступность

- Один writer на пересекающуюся область: координатор не редактирует её во время
  работы исполнителя. Параллельно допустимы независимые read-only исследования;
  не запускай конкурентные tracker/Git writes или вложенное дерево делегаций.
- Проектирование по умолчанию read-only; реализация пишет только в назначенной
  копии/области. Claim, worktree/session, commit/push и close остаются у координатора,
  если конкретная ограниченная операция явно не поручена иначе.
- Reviewer всегда новый отдельный read-only контекст `advanced`, не автор,
  проектировщик или исправитель данного кандидата. Модель может совпадать,
  контекст и происхождение должны быть независимыми. Для re-review разрешено
  продолжить только прежний reviewer-контекст, не контекст автора/исправителя.
- Поручение не расширяет разрешения инструментов или правила проекта.
- Проверяй доступность ID и разрешение делегирования до зависимой работы.
  Недоступен обязательный профиль/контекст — точный blocker, не молчаливый запуск
  `general`, другой модели или self-review. Review остаётся `unverified`.
  Можно продолжить независимое разрешённое чтение; изменение профилей или
  исключение из политики требует явного решения пользователя.
