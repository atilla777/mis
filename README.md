# MIS — Minimal Implementation Skills

MIS — небольшой пакет навыков для автономного выполнения SDLC в проектах с фиксированными соглашениями: **OpenCode 2.0 + Beads + Git + OKF-документы**. Две пользовательские команды: `/mis-plan` и `/mis-run`.

> **Состояние:** основа S1 создана: три portable-методики, общая библиотека и две точки входа. `/mis-plan` и `/mis-run` пока **только заготовки**: сообщают об отсутствии реализации и ничего не меняют. Планирование и выполнение появятся в S2–S4 по [плану](docs/build/plan.md).

## Начать разработку MIS

1. Клонировать публичный репозиторий [atilla777/mis](https://github.com/atilla777/mis).
2. Открыть репозиторий в OpenCode и попросить: «Следуй `AGENTS.md`. Выполни первую незавершённую сессию из `docs/build/plan.md`».
3. В каждой новой сессии повторять эту команду, не передавая историю предыдущих разговоров.
4. Хранить прогресс **только** в [плане](docs/build/plan.md) и Git. Не устанавливать Beads/RIS для разработки самого MIS.

## Проверка основы S1

В отдельной временной копии проекта скопировать всё содержимое `skills/`
в `.opencode/skills/` (включая `LICENSE-RIS`), а `commands/opencode/*.md` —
в `.opencode/commands/`. Не устанавливать RIS и не регистрировать пакет в
исходном проекте MIS. Проверенные пути соответствуют OpenCode 2.0.32:
[skills](https://opencode.ai/v2/docs/skills),
[commands](https://opencode.ai/v2/docs/commands).

Проверить реальный реестр, подставив абсолютный путь тестового проекта:

```sh
opencode api get '/api/skill?location%5Bdirectory%5D=/absolute/test/project'
opencode api get '/api/command?location%5Bdirectory%5D=/absolute/test/project'
```

Ожидаются шесть `mis-*` скиллов и две команды; Beads для этой проверки не нужен.
Это проверка обнаружения, не готовности полного workflow. Методики заимствованы
из RIS под MIT; точный SHA и отличия — в [карте переноса](docs/build/source-map.md).
