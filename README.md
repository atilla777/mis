# MIS — Minimal Implementation Skills

MIS — небольшой пакет навыков для автономного выполнения SDLC в проектах с фиксированными соглашениями: **OpenCode 2.0 + Beads + Git + OKF-документы**. Команды: `/mis-plan`, `/mis-run`, `/mis-status`, `/mis-install` и `/mis-update`.

`/mis-plan` планирует native Beads; `/mis-run` выполняет одну Task/Bug в собственной worktree со spec по необходимости, независимым review, раздельным подтверждением Git/Beads-публикаций и recovery. Epic проверяется по собственным критериям. Проверки и их границы — в [плане](docs/build/plan.md).

`/mis-status [ID]` показывает компактное дерево незавершённых вех и задач с
иконками, реальной вложенностью и блокерами. Закрытые задачи и обычный `open`
скрыты. Только чтение, без claim и запуска следующей работы.

## Установка в проект-потребитель

Нужен существующий Git-проект с известными primary branch и remote, а также
установленные OpenCode, Python 3, bd и Dolt. Продукт/правила приложения остаются
авторскими: `AGENTS.md`, `docs/product/`, `docs/spec/`, `docs/rules/` с командами
проверок и стратегией разработки нужны перед plan/run. MIS не выбирает стек и
не устанавливает системные зависимости. Подробнее — [контракт проекта](docs/rules/project-contract.md).

Явный `/mis-install` устанавливает пакет и подготавливает отсутствующий Beads:
`.beads/`, **embedded Dolt**, история в **том же Git-репозитории проекта** через
`refs/dolt/data`. Существующую БД переиспользует без переинициализации. На новом
clone восстанавливает удалённую историю вместо создания пустой конкурирующей БД.
Публикации Git-кода и Dolt остаются раздельными эффектами.

### Готовая инструкция для ИИ-агента: первая установка

В новом проекте скилл ещё не обнаруживается. Дайте агенту этот запрос:

> Установи MIS в текущий проект из https://github.com/atilla777/mis.
> Клонируй источник вне проекта, проверь origin, получи свежую origin/main и
> зафиксируй полный commit SHA. Прочитай README и
> skills/mis-proj-op-install/SKILL.md из этой проверенной копии и выполни его.
> Используй embedded Beads в .beads/ с Dolt remote в том же репозитории,
> что Git origin проекта. Сначала проверь local и remote историю; существующие
> данные, AGENTS.md, hooks и настройки сохрани. Не создавай приложение, не
> устанавливай ПО, не начинай планирование. Проверь реестр, готовность проекта
> и обе публикации отдельно; сообщи, что готово и что блокирует дальнейшую работу.

Commit/push возможны только по разрешению пользователя/правилам проекта.
Если публикация нужна и разрешения ещё нет, добавьте к запросу:
«Разрешаю commit и обычную non-force публикацию только установки MIS/Beads
в установленный origin проекта после проверок и необходимого ревью».

### Копирование пакета вручную (без подготовки Beads)

1. Клонируйте MIS вне потребительского проекта. Из корня потребителя выполните:

   ```sh
   python3 /absolute/path/to/mis/scripts/install.py . --revision FULL_TARGET_SHA
   python3 /absolute/path/to/mis/scripts/install.py . --revision FULL_TARGET_SHA --apply
   ```

   Python 3 нужен только установщику, не навязывается приложению. Копируются
   только 14 `mis-*` скиллов со всеми ресурсами, `LICENSE-RIS`, пять фасадов
   `.opencode/commands/mis-{plan,run,status,install,update}.md` и запись ревизии
   `.opencode/mis-installation`. Читаются Git-объекты точного SHA, не рабочие
   правки checkout. Первый вызов — preflight, второй — запись; engine общий с
   update. Beads, RIS, конфиги, Formulas и инструкции разработки MIS не копируются.
   Повторная установка идентичных файлов безопасна; конфликтующие файлы и
   symlink-пути отвергаются **до копирования**, без перезаписи. При обновлении
   используйте безопасную процедуру `/mis-update` ниже.
   Не запускайте установщик одновременно с другим writer.
2. Проверьте diff и **включите пакет, пять command-файлов и запись ревизии в
   обычный коммит подготовки проекта**. Это рекомендуемый способ обеспечить
   их обнаружение в новых native worktree и новых сессиях. Если `.opencode/`
   уже игнорируется, измените правила ignore осознанно; установщик их не меняет.
   Не коммитьте другие локальные настройки или credentials из `.opencode/`.
3. Откройте **новую сессию OpenCode в корне потребителя**, затем:

   ```text
   /mis-install
   /mis-plan цель из docs/product/
   /mis-run подтверждённый-Task-ID
   /mis-status
   ```

   `/mis-install` явно подготавливает Beads и проверяет готовность; если уже всё
   настроено, переиспользует состояние. Это отдельные вызовы: планирование и статус только рекомендуют следующий шаг.
   `/mis-run` без ID выбирает одну допустимую работу. Разрешения на Git и общую
   Beads/Dolt историю должны быть заданы проектом; пакет их не подменяет.

Проверенная среда: **OpenCode 2.0.32, bd 1.3.1, embedded Dolt 2.4.1**.
Требуются реальные native `worktree_list/create`, `session_move` и отдельный
reviewer-контекст. Другие версии/engine modes требуют проверки capabilities.
При ignored/untracked установке новая worktree может не обнаружить MIS:
текущий flow сохраняет проверенный исходный installed root для чтения методов
после move, но новая независимая сессия не наследует этот контекст. Для неё
используйте versioned установку выше, а не скрытое копирование во время Task.

## Обновление установленного MIS

### Готовая инструкция для ИИ-агента: обновление

> Выполни `/mis-update`: обнови только установленный пакет MIS из проверенной
> свежей origin/main https://github.com/atilla777/mis, зафиксировав полный SHA.
> Соблюдай AGENTS.md, отдельную worktree и ревью, если они требуются проектом.
> Сначала полный preflight, затем apply, проверка реестра и no-op повтор.
> Не меняй Beads, зависимости, AGENTS.md и настройки. Сохрани локальные правки;
> при конфликте остановись без force. При разрешённой публикации подтверди
> удалённый SHA отдельно. Не начинай следующую задачу.

`/mis-update [ревизия]` обновляет только пакет MIS из проверенного внешнего
checkout `https://github.com/atilla777/mis`. Без аргумента скилл проверяет свежую
`origin/main`; целевая ревизия всегда фиксируется полным SHA. Зависимости,
OpenCode, Beads и настройки проекта не обновляются.

Скрипт скилла сравнивает Git-снимки установленной и целевой ревизий, проверяет
**весь** набор до записи, отказывается затирать локальные правки и неизвестные
ресурсы внутри управляемых скиллов. Symlink и hard-link назначения отвергаются;
upstream payload поддерживает только обычные файлы Git mode `100644` (Python
ресурсы запускаются через `python3`). Устаревшие неизменённые файлы удаляются
по одному; прочие скиллы/команды сохраняются. По умолчанию — только preflight:

```sh
python3 /absolute/path/to/mis/skills/mis-proj-op-update/scripts/update.py /consumer/worktree --source /absolute/path/to/mis --revision FULL_TARGET_SHA
```

Для применения добавьте `--apply`. Ревизия записывается последней в
`.opencode/mis-installation`; повтор при точном совпадении — no-op. У старой
установки записи может не быть (новый установщик записывает её сразу):
сначала установите исходный SHA сравнением всего пакета и передайте
`--from-revision FULL_INSTALLED_SHA`. Для первой установки из чистого checkout
это SHA его HEAD. Не угадывайте базовую ревизию для обхода конфликтов.
Старый формат записи snyrk поддерживается. Скрипт читает Git-объекты, а не WIP.

Проверка origin/свежести remote, разрешения, worktree, независимое ревью и
публикация выполняются скиллом по правилам потребителя. Скрипт не делает fetch,
commit/push и не является транзакционным или конкурентным установщиком.
После обновления рекомендуется новая сессия, чтобы не смешивать загруженные
старые инструкции с новыми.

## Начать разработку MIS

1. Клонировать публичный репозиторий [atilla777/mis](https://github.com/atilla777/mis).
2. Открыть репозиторий в OpenCode и попросить: «Следуй `AGENTS.md`. Выполни первую незавершённую сессию из `docs/build/plan.md`».
3. В каждой новой сессии повторять эту команду, не передавая историю предыдущих разговоров.
4. Хранить прогресс **только** в [плане](docs/build/plan.md) и Git. Не устанавливать Beads/RIS для разработки самого MIS.

## Проверка обнаружения пакета

После установки проверяйте реальный реестр. Не устанавливайте пакет в
исходный проект MIS. Пути OpenCode 2.x подтверждены документацией и 2.0.32:
[skills](https://opencode.ai/v2/docs/skills),
[commands](https://opencode.ai/v2/docs/commands).

Проверить реальный реестр, подставив абсолютный путь тестового проекта:

```sh
opencode api get '/api/skill?location%5Bdirectory%5D=/absolute/test/project'
opencode api get '/api/command?location%5Bdirectory%5D=/absolute/test/project'
```

Ожидаются четырнадцать `mis-*` скиллов и пять команд; Beads для этой проверки не нужен.
Это проверка обнаружения, не готовности полного workflow. Методики заимствованы
из RIS под MIT; точный SHA и отличия — в [карте переноса](docs/build/source-map.md).

## Проверки разработки

```sh
python -B -m unittest discover -s tests -p 'test_*.py' -v
python -B tests/s2_beads_smoke.py
python -B tests/s3_execution_smoke.py
python -B tests/s4_publication_smoke.py
python -B tests/s9_installation_smoke.py
```

Smoke-проверки требуют OpenCode/bd/Dolt и создают временные проекты с локальными
remotes под `/tmp/opencode`, не модельные workflow. Для ручного повторения S5:
`python -B tests/s5_prepare_pilots.py` создаёт две чистые подготовленные копии,
но **не** планирует/исполняет работу. В каждой запустите две команды выше в
новых сессиях; проверьте Task/Epic, Git и Dolt remote отдельно. Доказательства
двух пилотов и ограничения приёмки хранятся только в плане разработки.
