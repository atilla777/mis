# `mis-run`: автономная разработка

## Вход и выбор

`/mis-run <ID>` выполняет или возобновляет конкретную Task/Bug. Без ID — выбирает одну подходящую готовую работу из Beads, с приоритетом собственной прерванной работы, если владение и состояние подтверждены. Никакой отдельной команды `next`.

## Один запуск — один результат

1. Проверить существование Bead, разрешения, владельца/claim, реальные блокирующие связи, контекст и условия завершения. При возобновлении установить реальные уже достигнутые эффекты и не повторять опубликованные операции.
2. Подготовить либо **переиспользовать** связанную с Beads ID рабочую копию через **нативные средства OpenCode 2.0** (`worktree_list`, `worktree_create`, `session_move`). Проверить Git association, branch, путь, чистоту/посторонние изменения. `session_move` может применяться только на границе вызова — не работать с файлами по предположению о мгновенном переключении.
3. Прочитать актуальную задачу, относящиеся к ней product/spec/rules, изучить код. Определить технический подход и нужную глубину внутреннего плана; не требовать его сохранения в Beads/файле.
4. Реализовать и проверить работу. Стратегия TDD/standard, тестовая пирамида, UI/screenshot checks, CI и т. п. берутся исключительно из правил проекта-потребителя. Самостоятельно решать локальные технические вопросы в согласованной области.

   Уточнить по итоговой реализации сохранённый в Task способ увидеть изменение: условия, каталог/ревизия, точка входа или команда, действия и ожидаемый эффект. Выполнить доступную безопасную проверку сценария; если она невозможна, явно указать непроверенную часть и причину, не подменяя её успешными автотестами. Обязательный критерий Task нельзя считать выполненным без требуемой проверки. Сохранить краткий пользовательский/технический эффект и инструкцию в существующей записи результата Task, без отдельного журнала или demo-файла.
5. При появлении нового устойчивого реализованного поведения создать/обновить `docs/spec/` через отдельную атомарную методику. Не создавать spec на каждую техническую задачу; не считать код единственным источником правил. Реализация, проверки и spec должны соответствовать.
6. Провести необходимое **независимое ревью** проверяемого набора изменений, устранить значимые замечания и перепроверить изменённый результат. Для изменений кода ревью — стандартный gate; проектные правила могут предписывать дополнительные проверки. Не выдавать самопроверку за независимое ревью.
7. Опубликовать точный проверенный Git-result, подтвердить фактическую удалённую ветку/ревизию; записать результат/ссылки, закрыть Beads ID и независимо проверить нужную Beads/Dolt-публикацию. При каждом сбое сохранять подтверждённые частичные эффекты.
8. Если Task — часть Epic, проверить закрытие Epic по завершённым обязательным задачам **и собственным критериям вехи**. Не закрывать Epic автоматически по одному факту «дети закрыты», когда его результат не достигнут. Вывести отчёт и следующее действие, не запускать очередь до бесконечности.

## Worktree

Epic worktree не нужен. Каждая задача с Git-изменениями имеет собственную устойчивую рабочую копию. MIS не управляет Worktrunk и не внедряет собственный адаптер Git-worktree. Копию с незавершёнными изменениями сохранять, не удалять с `force`. В отдельных локальных/non-Git операциях не создавать пустую Git-ветку ради процедуры. Общие БД, порты, сервисы и Beads-данные не изолируются Git worktree автоматически.

## Вопросы человеку

Run сначала изучает факты и прежние ответы; определённую Task можно начать с
ограниченного интервью через `mis-port-op-interview`. Допуск к этому процессу
не означает достаточности требований для claim/зависимой реализации. Критерий
интервью — известны входы/выходы, ограничения и проверяемый результат одной работы.
Подтверждённые ответы сохраняются bounded update/read-back в description/acceptance
существующей Task, затем тот же run продолжается без обязательного `/mis-plan`.
При достаточных данных интервью пропускается; поздний пробел приостанавливает
только зависимую реализацию до уточнения.

Если выяснилось, что надо изменить объём, разделить Task или перестроить граф,
сохранить факты и рекомендовать `/mis-plan <ID и дельта>`. Незавершённые
prerequisites, чужое владение, конфликты требований и ограничения среды остаются
blockers до реального устранения; интервью их не обходит. Отдельной обязательной
команды/стадии уточнения или задачи «согласовать требования» нет.

Только при реальной продуктовой развилке, противоречии авторским требованиям, невозможном разрешении конфликта, недоступной критичной возможности либо отсутствии необходимого разрешения. Не спрашивать «продолжать?», «согласовать дизайн?», «можно публиковать?» после каждого шага в рамках уже порученной и допустимой операции.

## Граница завершения

Успех `mis-run` означает завершение **одной выбранной работы**, а не выполнение всех Task Epic. Если выявлена самостоятельная дополнительная работа за пределами области, её можно зарегистрировать в Beads с проверкой отсутствия дублей; текущая работа не расширяется бесконтрольно.
