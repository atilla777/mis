# MIS Sessions

Отдельный пользовательский плагин Omarchy Shell: раскрывающийся список проектов
и незавершённых задач dispatcher, до четырёх обычных окон OpenCode на проект.
Herdr/tmux не нужны. Фокус, fullscreen и переключение рабочих столов остаются
штатными Hyprland. Пакет проекта, dispatcher, claim и отправка `/mis-run` не меняются.

## Поведение

- Проекты обнаруживаются по `metadata.mis_dispatcher` основных OpenCode-сессий,
  без обхода диска и ручного реестра. Native children не получают отдельных окон.
- Проверяются Beads-связь и canonical `.beads`; все обращения к Beads read-only.
- На проект выделяется именованный рабочий стол `mis-<hash canonical path>`.
  Другие рабочие столы, окна и биндинги пульт не изменяет.
- До четырёх окон: одно занимает область, два — две колонки, три/четыре — сетка.
  Новые задачи заполняют свободные места, но не вытесняют выбранные.
- Список содержит все незавершённые задачи; выбранная видимая фокусируется,
  скрытая заменяет последний выбранный слот того же проекта.
- Beads closed при отсутствии active/pending во всём native семействе убирает
  задачу и освобождает слот. Idle, failed и ожидание человека не означают completed.
- Сбой/неполный inventory не очищает окна: старый снимок остаётся с диагностикой.
- Клиенты OpenCode открывают только проверенные существующие Session ID, без
  prompt/command/interrupt/delete/автоответов. При смене слота завершается только
  принадлежащий пульту клиентский процесс, не сервер и не process group.
- Пульт не закрывает пользовательские терминалы, даже если в них та же сессия.

## Границы

Linux, Omarchy Shell/Quickshell, Hyprland 0.56 Lua API, Kitty, Python 3, OpenCode 2
shared service и Beads. Собственный shell plugin и helper поставляются в
`integrations/omarchy/mis.sessions/`; устанавливаются отдельно, не через
`/mis-install` или `/mis-update`. Не заменяют стандартный bar/workspace plugin.
UI-state хранит только снимок/четыре назначения/фокус, не очередь задач.
Ошибки API не являются основанием запускать новый сервер с `--standalone`.

Живая GUI-проверка, проверка отключения TUI и установка в пользовательский HOME
фиксируются отдельно в едином плане; unit tests не доказывают их автоматически.
