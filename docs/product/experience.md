# Пользовательские команды

## `/mis-plan [цель | Epic ID | Task ID]`

Формирует или корректирует проектный план на основании `docs/product/`, реально реализованного состояния и Beads. Может создать новый Epic и Tasks, дополнить существующий Epic или зарегистрировать отдельную Task. Проводит интервью только при продуктовой неопределённости.

## `/mis-bug [описание | ID и уточнение]`

Собирает сведения и ограниченно исследует один дефект, неудобство или запрос
нового поведения; сохраняет подробный native Bug либо дополняет исходную запись.
Различает факты/гипотезы и принятые ожидания, сохраняет условия, проблематику,
исследование и критерии разрешения. Проверяет дубли и отдельно публикацию Beads.
Без реализации/claim/close; рекомендует обычный run, если работа достаточно
определена и посильна. [Полный контракт](bug-intake.md).

## `/mis-run [Task ID | Bug ID]`

Без ID выбирает следующую доступную/свою незавершённую работу. С ID выполняет или продолжает ровно её. Включает разработку, документацию по необходимости, независимое ревью, Git/Beads-публикацию и проверку вехи.

Определённая задача без реальных blockers → `/mis-run <ID>`, даже если сначала
нужно ограниченное интервью; достаточность для claim проверяется внутри run.
Неясный объём, мешающий выделить задачу, либо изменение объёма/декомпозиции/графа
→ `/mis-plan`. Простой недостающий ответ внутри Task не требует перепланирования.
Реальные prerequisites, владение, конфликты и ограничения среды требуют устранения,
а не автоматического возврата в plan или обхода интервью.

## `/mis-status [Epic ID | Task ID | Bug ID]`

Только чтение: компактное дерево незавершённых Milestone/Task/Bug с реальной
вложенностью, иконками и одной рекомендацией. Без ID — весь проект, с ID — его
поддерево. Закрытые задачи скрыты, обычный `open` и тип Task не повторяются.
Показываются начатая работа, реальные блокеры, повышенный приоритет и существенные
исключения. Счётчики вех — закрытые/все прямые задачи, не выполнение критериев.
Самостоятельные задачи идут отдельно, без искусственной вехи. Неполное чтение
явно отмечается; команда ничего не меняет и не запускает.

## `/mis-update [ревизия]`

Обновляет только установленный пакет MIS из доверенного upstream до проверенного
полного commit SHA (без аргумента — свежая `origin/main`). Сравнивает весь пакет
с записанной исходной ревизией до записи; локальные правки и неизвестные ресурсы
не затирает. Удаляет только устаревшие неизменённые файлы прежнего пакета.
Ревизия установки записывается после файлов, точный повтор — no-op. При отсутствии
записи нужна доказанная исходная ревизия. Worktree, проверки, ревью и разрешение
публикации определяются правилами потребителя. Beads, зависимости и настройки
не меняет, следующую задачу не запускает. Не обещает транзакционность при I/O-сбое.

## `/mis-install [ревизия]`

Явная первоначальная установка MIS и подготовка Beads в существующем Git-проекте:
embedded Dolt в `.beads/`, публикация истории через `refs/dolt/data` того же
проектного Git remote. Существующую БД проверяет и переиспользует; при remote
истории восстанавливает её, не создаёт пустую конкурирующую БД. Не устанавливает
ПО и не выдумывает продукт/правила. Ошибки/неполнота/конфликт настроек — blocker,
не разрешение на reinit. Пакет использует общий engine с update и записывает
точный source SHA; повтор — no-op. Git и Dolt проверяются отдельно. Установка
в пустой реестр начинается чтением skill из доверенного внешнего checkout;
готовый запрос для ИИ и ручные команды приведены в README. Не запускает plan/run.

## Отчётность планирования и выполнения

Короткий, конкретный итог с пиктограммами, без внутреннего журнала этапов:

- ✅ Что выполнено и что изменилось с точки зрения пользователя. Для технической работы — наблюдаемый технический результат и честное указание, если пользовательское поведение не изменилось.
- 👀 Как увидеть результат: из какого каталога/ревизии, что запустить или открыть, необходимые условия, короткие действия и ожидаемый эффект. Отделять проверенный сценарий от предложенной, но не выполненной инструкции. Если результат пока недоступен (например, нет deploy), явно указать ограничение; Git push не означает доступность функции в работающем приложении.
- 🧪 Какие проверки/ревью проведены; что не удалось проверить.
- 📚 Какие product/spec/rules документы изменены (или почему не нужны).
- 🔗 Какие Beads ID, зависимости, Git-коммиты/refs и публикации подтверждены.
- ⚠️ Какие реальные блокировки/неполные эффекты остались.
- ➡️ **Одно** наиболее полезное следующее действие и готовая команда `/mis-run <ID>` либо `/mis-plan <цель>`.

Отдельная команда `next` не создаётся. Отчёт *рекомендует*, но не запускает автоматически следующую самостоятельную Task. Не маскировать частичную Git или Dolt-публикацию словом «готово».

Для планирования описывать ожидаемый, а не уже реализованный эффект; 👀 может ссылаться на сохранённый в Task сценарий будущей проверки. Для выполнения инструкция соответствует итоговой реализации. Команды автотестов не заменяют пользовательский сценарий; для CLI/API/технической работы допустима команда с наблюдаемым выводом вместо UI. Демонстрация не разрешает скрытый deploy, опасные действия или изменение production-данных.

## Диалог

Не требовать повторных согласований уже выраженных требований, обычных технических шагов и предусмотренной публикации. Фактическая пользовательская область действий и разрешения среды обязательны; опасные операции или существенное изменение цели нельзя разрешать одной фиктивной политикой автоматического принятия.
