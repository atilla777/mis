# MIS Dispatcher

`mis-dispatcher` — необязательный Go-бинарник для очереди **одного** подготовленного
MIS-проекта. Выбирает самые старые native ready Task/Bug и отправляет каждой
`/mis-run <ID>` в отдельной обычной OpenCode 2 сессии. Не планирует, не использует
LLM для оркестрации, не создаёт worktree, не пишет код и не меняет правила
публикации/ручного merge. Всё исполнение, claim, проверки, review и Git/Beads
остаются существующему MIS и правилам потребителя.

`mis-dispatcher --status [ID]` — независимый режим просмотра того же проекта:
один read-only отчёт о незавершённых вехах и задачах, без модели и запуска scheduler.

## Сборка и установка

Нужны Go **1.25+** для сборки, Python 3 только для bootstrap; для работы — Git,
Beads и OpenCode 2 с поддерживаемым API. Проверенный baseline: OpenCode 2.0.32,
bd 1.3.1. Установленный в проект пакет MIS должен уже включать протокол
`MIS dispatcher reservation v1`: сначала обычный `/mis-update`, если пакет старый.
Dispatcher проверяет обнаружение команды/протокола до записи.

Проверка исходного checkout без установки:

```sh
go test -race ./...
go build -o /tmp/opencode/mis-dispatcher ./cmd/mis-dispatcher
```

Установка **один раз для пользователя** из проверенной копии MIS:

```sh
git remote get-url origin
# Должен быть https://github.com/atilla777/mis (либо его SSH URL).
git fetch origin main
git rev-parse origin/main
# Проверьте целевую ревизию/исходники и используйте её полный SHA:
python3 scripts/install-dispatcher.py FULL_REVIEWED_COMMIT_SHA
```

Bootstrap должен сам совпадать с Git blob целевого SHA. Он проверяет origin и
достижимость SHA из локальной `origin/main`; **свежесть fetch и доверие ревизии
подтверждает вызывающий**, не скрипт. Читает Go sources из Git objects, не WIP;
запускает unit tests, собирает и атомарно заменяет
`~/.local/bin/mis-dispatcher`. Конфиги не трогает; повтор безопасен. Старый бинарник
сохраняется при build/test failure. Symlink/hardlink назначения отвергаются.
Добавьте `~/.local/bin` в PATH, если его там нет. Go может скачать зависимости,
проверяемые `go.sum`; системные пакеты и новые версии toolchain не устанавливаются.
Автоматического сетевого обновления нет. Для обновления бинарника — тот же
явный bootstrap с новой проверенной ревизией, не новая команда диспетчера.

`/mis-install` и `/mis-update` продолжают обслуживать только проектный пакет;
**не собирают глобальный бинарник** на каждом проекте. Бинарник не копируется
в проект, systemd/tmux/демоны не создаются.

## Запуск

```sh
cd /path/to/project
mis-dispatcher
```

Первая проверка сразу, дальше — интервал конфигурации. Вывод: канонический проект,
лимиты, ready/active/open/started, ID и состояния связанных сессий, предупреждения.
Проект — первый checkout из native Git worktree inventory; вложенный каталог,
linked worktree и symlink ведут к одному каноническому пути. Проверяются AGENTS,
docs/product/rules/spec, installation record и `bd where` в canonical `.beads`.
Нет скрытого init/регистрации/сканирования каталогов. Ambient Beads DB/server
redirect overrides отвергаются. Один checkout = один MIS-проект.

Один экземпляр на канонический путь: OS `flock` в пользовательском cache,
имя — SHA256 пути; kernel освобождает lock при выходе/падении. Lock-файл не
удаляется (иначе возможны два заблокированных разных inode). Разные проекты
независимы и имеют собственные лимиты, не общекомпьютерную квоту.

## Разовый статус без LLM

```sh
mis-dispatcher --status       # весь незакрытый план
mis-dispatcher --status ID    # точный ID и его поддерево
mis-dispatcher --help
```

Компактный Markdown-список в формате `/mis-status`: цветные Epic, вложенные
Task/Bug, закрыто/всего прямых детей, ○/▶/🔒/🐛, P0/P1, assignee и просроченные
сроки. Закрытые задачи скрыты, но участвуют в счётчиках. Закрытые ancestors с
открытыми потомками и явно выбранный закрытый root остаются как контекст.
Пустые открытые Epic видимы. Standalone записи — «Без вехи».

Parent берётся только из native `parent-child`, blockers — из направленных
`blocks`, не из префикса ID. Закрытый prerequisite не блокирует. Внешние blockers
показаны inline, без отдельного дерева. Полный режим читает unlimited all-status
inventory всех типов; ID-режим — точный root, полные direct-child selections
рекурсивно и необходимые ancestors/prerequisites. У ancestors вне выбранного
поддерева состав остальных детей не проверяется, поэтому счётчик не выводится.
Sibling order — ID; цвета Epic назначаются по отсортированным ID прочитанного
inventory, с повтором палитры после шести. ▶ означает Beads `in_progress`,
не фактическую активность агента.

Нужны только Git и доступная Beads-база текущего проекта. Canonical checkout и
проверка `bd where` те же, что у scheduler; ambient DB redirects отвергаются.
Не нужны OpenCode/API, установленный пакет MIS, docs/product/spec, remote,
scheduler YAML и свободный scheduler lock. Статус можно читать при работающем
диспетчере. Все обращения к Beads — `--readonly`; нет init/claim/update,
Git/Dolt fetch/pull/push, session create или рекомендаций следующего действия.
Существующие `/mis-status` и скилл остаются доступны без установленного бинарника.

Неизвестные типы/статусы печатаются явно. Некорректные parent-связи вынесены в
«⚠️ Связи не подтверждены»; недоступные endpoints, циклы и ошибки чтения сообщаются
как диагностика. Ошибка или несогласованность → exit 1, не ложный пустой план;
если возможно, перед ошибкой печатается доступная часть. Успех → exit 0.
Несколько CLI-чтений не являются транзакционным снимком: замеченные расхождения
связей отмечаются, но отсутствие гонок с concurrent writers не гарантируется.

Связи родителей и блокировок читаются через native `bd dep list` пакетами до
128 ID, а не отдельным процессом на каждую запись. Кэш не используется; закрытые
записи по-прежнему учитываются в составе вех. В ID-режиме поиск прямых детей
остаётся отдельным чтением для каждого узла выбранного поддерева.

Проверка реального CLI без установки бинарника и без моделей:

```sh
go build -o /tmp/opencode/mis-dispatcher ./cmd/mis-dispatcher
python3 -B tests/status_cli_smoke.py /tmp/opencode/mis-dispatcher
```

Smoke создаёт только disposable Git/Beads fixture, проверяет дерево, ID scope,
linked worktree и неизменность issue inventory/Git HEAD/Dolt status. Явный `TMPDIR`
поддерживается Go CLI transport и smoke при ограничениях системного temp.

## Конфигурация

Слияние по отдельным параметрам: **Defaults → Global → Project**.
Отсутствующие файлы допустимы. Global:
`$XDG_CONFIG_HOME/mis/dispatcher.yaml`, иначе `~/.config/mis/dispatcher.yaml`.
Project: `<canonical-root>/.mis/dispatcher.yaml`.

```yaml
scheduler:
  interval: 60s
  max_concurrent_tasks: 6
  max_open_tasks: 12
  selection: oldest_ready_first
```

Это значения по умолчанию; duration — Go duration, положительный. Лимиты — целые
неотрицательные; `0` запрещает новые запуски. Единственная selection —
`oldest_ready_first`: `created_at`, затем ID. Priority не меняет порядок.
Неизвестные поля, неверные значения и несколько YAML documents — ошибка.
Каждый цикл перечитывает оба файла. При ошибке новых запусков нет; исправьте
конфиг, следующая проверка повторится с последним корректным интервалом
(до первой успешной загрузки — 60s). Снижение лимита не останавливает сессии.

## Активные и открытые задачи

Учитываются только явно связанные с dispatcher задачи текущего проекта,
включая native дочерние агенты, не ручные независимые сессии.

| Состояние | Проверяемый сигнал | Активный слот | Открытый слот |
| --- | --- | --- | --- |
| RUNNING | native `/api/session/active`, без ожидания человека | да | да |
| WAITING_USER | pending forms или permissions | нет | да |
| PAUSED | idle, interrupted, неизвестная причина остановки | нет | да |
| FAILED | structured session outcome `failed` | нет | да |
| COMPLETED | Beads `closed`, сессия не выполняется/не ждёт | нет | нет |

Idle или успешный ответ модели **не** закрывают задачу. Beads closed — источник
завершения задачи, не самостоятельное доказательство обеих remote-публикаций:
их подтверждает `/mis-run`, включая recovery частичной Dolt-публикации.
При closed + running/waiting выводится противоречие и новые запуски блокируются.
Если один дочерний агент ждёт, а другой действительно работает, задача остаётся
активной. Собственное pending-ожидание исключает сессию из активности. Native API
не различает работающего родителя и родительский drain, ожидающий ребёнка:
если родитель всё ещё native active без собственного pending-запроса, слот
консервативно занят. Ожидающий background child сам по себе не освобождает его.
Ручное возобновление той же сессии снова занимает активный слот. Превышение
лимита вручную не прерывает агентов, но запрещает новые запуски. Новые отправки
занимают активный слот уже в текущем цикле, до проекции активности API.

## Связь, claim и восстановление

До create в Beads guarded update сохраняет `metadata.mis_dispatcher`: JSON-строка
с `version=1`, `project`, `task`, заранее случайно сгенерированным `session` и
`phase=reserved`. OpenCode create получает **тот же supplied Session ID** и ту же
структуру в session metadata. Назначенные, уже зарезервированные, не-ready,
неизвестные типы/даты не запускаются. Native ready учитывает зависимости;
свежая проверка перед резервированием и `/mis-run` перепроверяют допуск.

**Claim один:** только существующий atomic `bd update --claim` внутри `/mis-run`,
после проверки требований. Dispatcher не назначает actor и не меняет status.
Обновлённый MIS проверяет reservation/current Session ID перед claim. Защита
кооперативная: произвольный внешний `bd --claim` вне MIS может её проигнорировать;
конфликт не даёт права force/reclaim. Нельзя одновременно использовать старый
загруженный run flow, не знающий протокола, для той же очереди.

Create с неизвестным результатом → сначала GET заранее сохранённого Session ID
и сравнение metadata. Совпало — продолжение запуска без нового create;
не удалось подтвердить — резервирование сохраняется, автоматического retry нет.
Перед command сохраняется `phase=submitted`. Неизвестная отправка, отказ API
или crash между этой записью и command **никогда не ведут к повторной отправке**.
Это намеренно at-most-once, не гарантия exactly-once доставки.

После restart связи восстанавливаются из Beads/OpenCode, без локальной task DB.
Обычные ранее запущенные сессии продолжают учитываться. Неполный запуск
(`reserved`), пропавшая сессия, несовпадающая metadata или потерянная Beads-связь
требуют ручной проверки; неоднозначный inventory блокирует новые запуски проекта,
чтобы не занизить лимиты. Dispatcher не удаляет сессии и не освобождает reservation.

Native дочерние сессии могут наследовать `mis_dispatcher` metadata основной
сессии: поле `session` по-прежнему указывает на основной запуск, не на ребёнка.
Это не конфликт, если metadata совпадает со связью Beads и цепочка `parentID`
доходит до точно связанной основной сессии. Отдельная сессия с той же metadata
без подтверждённого родства по-прежнему блокирует новые запуски.

Пользователь открывает указанный Session ID через обычный OpenCode, проверяет
историю и отвечает на вопросы/permissions там. Если исходная команда точно не
отправилась, её можно явно выполнить **в той же** пустой сессии. Нельзя вслепую
удалять metadata/создавать другую сессию: сначала подтвердите отсутствие writer
и частичных эффектов. Dispatcher не посылает «продолжай», не читает свободный
текст LLM и не отвечает вместо человека.

Временная недоступность bd/API: предупреждение, без новых запусков, следующая
проверка по интервалу. На запрос CLI ограниченное время, нет внутренних
бесконечных retries. API transport — `opencode api`, с native server discovery и
authentication, не unauthenticated HTTP-клиент и не процесс AI-исполнителя.

**Ctrl+C / SIGTERM** завершают только dispatcher и его клиентские CLI-вызовы.
Никаких interrupt/delete/stop запросов агентам не отправляется. Уже принятые
OpenCode сервером сессии продолжают работу и доступны в обычном интерфейсе.

## Границы MVP и проверки

Linux/Unix flock, существующий canonical Git/MIS checkout и поддерживаемый
OpenCode 2 API. Нет БД dispatcher, UI, subcommands, фонового режима, контроля
токенов/подписок, автозапуска следующих этапов вне `/mis-run`, автоматического
repair незавершённых отправок и гарантии against произвольных внешних writers.
Переезд canonical checkout требует ручного согласования сохранённых metadata.

Go unit tests используют управляемые Beads/OpenCode doubles, не реальные модели;
покрывают порядок/зависимости/лимиты/повторы/неизвестные эффекты/интерактивность/
restart/cancel, API shape, конфигурацию и межпроцессную блокировку с crash.
Python bootstrap tests работают в disposable HOME с fake Go, не устанавливают
бинарник пользователю. Реальные CLI/API contract checks не доказывают новый
fresh-model end-to-end пилот dispatcher; границы evidence — в едином плане.
